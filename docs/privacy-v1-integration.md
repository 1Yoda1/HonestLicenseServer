# Интеграция документов HonestFlow v1.0

Выполнено локально 2026-11-04. Документы подготовлены к утверждению и последующей
публикации. Production не проверялся, не изменялся и приём заявок не включался.
Лицензирование, HonestFlow и HonestDesk в этой задаче не изменены.

## Исправленные расхождения

1. В прежнем коде автоматически удалялись New/Rejected, но Completed оставался.
   Теперь удаляются также завершённые заявки: 30 суток отсчитываются от входа
   в текущий статус, для Completed/Rejected это закрытие. Прежнее правило для
   New сохранено. Повторное открытие начинает новый отсчёт, InProgress защищён
   от автоматического удаления; повторная запись того же статуса срок не меняет.
   Штатный опрос начинает удаление за один интервал (15 минут) до предельной даты,
   чтобы не добавлять 15 минут после 30 суток. При простое API или занятом WAL
   абсолютное соблюдение срока требует эксплуатационного контроля.
2. `/privacy/` была заглушкой, зависела от JS/API и доступности приёма. Теперь
   содержит полный текст политики v1.0 в существующем дизайне и работает без JS.
3. Полный текст согласия ранее загружался только при доступном приёме и мог
   отличаться от опубликованной редакции. Теперь отдельный текст v1.0 доступен
   в раскрытии у обязательного, изначально снятого флажка. Несовпадение версий
   сайта и API блокирует отправку; после 409 согласие запрашивается повторно.
4. Сервер допускал PreContract и произвольные версии/тексты из конфигурации.
   Для этой редакции допускается только Consent, версии 1.0 и точные встроенные
   тексты. БД сохраняет серверное время, версию, точный текст согласия, основание
   и версию политики. Переданный клиентом текст доказательство не заменяет.
5. Старый Enabled=true сам по себе не разрешает новый выпуск: нужны также
   явное ApprovedDocumentVersion=1.0 и последующее разрешение владельца на запуск.
   Репозиторные настройки: Enabled=false, ApprovedDocumentVersion пусто.

## Соответствие цепочки обработки

- Поля формы соответствуют разделу 2 политики. Модели ККТ входят в комментарий;
  IP, User-Agent и UTC-время сохраняет сервер. Паспорта/пароли/чувствительные
  сведения не запрашиваются; добавлена просьба не помещать их в свободное поле.
- Email и InventorySystem остаются в старом контракте API для совместимости;
  текущая форма их не собирает и передаёт null. Это не новые поля формы.
- Заявки хранятся в ConnectionRequests, уполномоченный оператор работает через
  admin API/HonestDesk. Публичного списка заявок нет.
- Уничтожение охватывает строку со всеми полями, доказательством согласия и
  старой SMTP-метаинформацией, а также связанные строки AuditEvents.
  Удаление выполняется транзакционно с secure_delete и проверкой очистки WAL.
  Отсутствие персонального маркера в файле БД/WAL проверяется интеграционным тестом.
- Отзыв предусмотрен по mailto:spi@morkovka.tech, отдельно от отправки формы.
  Снятие флажка не является автоматическим отзывом уже отправленной заявки.
  После проверки обращения оператор применяет существующее удаление в HonestDesk.
- В серверном потоке заявок нет SMTP-клиента/отправки писем, интеграции MAX нет.
  Новых юридических страниц не создавалось; используются `/privacy/` и форма.

## Что остаётся подтвердить до публикации/включения

- Физическое размещение рабочей БД, резервных копий и журналов в РФ — сведения
  из предоставленных материалов, а не факт, проверенный исходным кодом.
- Уничтожение старых бэкапов, журналов, исторических SMTP-писем и иных внешних
  копий API не выполняет. Их сроки и порядок удаления должны быть подтверждены.
  Восстановление из старого бэкапа не должно возвращать удалённые ПД в обработку.
- Код не подтверждает исполнение email-отзывов, состав уполномоченных лиц,
  договорные роли поставщиков, адрес для корреспонденции и юридические действия,
  перечисленные в инструкции владельца. Их нельзя считать выполненными.
- Политика отдельно допускает обработку необходимых договорных данных. Этот
  поток не определяет заключение договора и удаляет все Completed; отдельные
  договорные сущности и лицензирование не изменялись.
